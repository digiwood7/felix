## ✅ 닫힌 것

### 1. 되묻기 기준선에 내림값이 남아 있었다 **[재현]**

`e3c1588` 이 배지 판정에서 내림을 걷어냈는데 **되묻기 게이트에는 그 자가 그대로 남아 있었다.**

17:30 예약 (금식 표시 `11:00` / 판정선 `11:30`):

| 마지막 식사 | 되묻기 | 결과 |
|---|---|---|
| 11:00 | 떴다 | "물 외에 없었다" → 🟢 |
| **11:20** | **안 떴다** | 🟡 에 갇힘 |

**6시간 10분을 지킨 환자가, 6시간 30분 지킨 환자보다 나쁜 결과를 받았다.** 게다가 빠져나올 길이 없다 — 배지는 그대로 접수처에 나간다. 예약 분이 00 이 아닌 모든 예약(5분 단위이므로 **12개 중 11개**)에서 일어났다.

`deadlineBefore()` 를 두어 판정선을 한 곳에서만 계산하고, 되묻기와 배지가 같은 함수를 읽게 했다. **자가 둘로 갈리는 것이 원인이었으므로 계산 지점을 하나로 줄이는 것이 재발 방지다.**

→ PRD §8 F2 · §9.4

### 6. 금식 시작 전에 금식을 물었다 **[재현]**

`CheckCta` 가 "검사 당일인가" 만 봤다. 그래서 **당일이지만 금식이 아직 시작되지 않은 시간대**가 당일과 같은 강조를 받았다.

```
17:30 예약        →  금식 시작 11:00
앱이 권하는 시점   →  "검사 당일 아침에 답해 주세요"
아침 8시의 질문    →  "6시간 금식 하셨나요?"
```

**앱이 스스로 권한 시점에 문항이 성립하지 않았다.** 환자는 답할 수 없는 질문에 "네" 를 누르고, 그 답은 그 시점에 참이 아니다.

갈래를 셋(`today` / `early` / `later`)으로 늘렸다. **막지는 않는다** — 강조와 문구만 바꾸고 링크는 살려 둔다.

→ PRD §9.4.1

### 7. 당일 안에서 상황이 바뀌면 카드가 못 따라온다 **[코드]**

카드 stale 판정이 `savedOn !== examDate` — **날짜 단위**였다.

> 아침 8시에 🟢 를 만들고 · 11시에 약을 먹고 · 17:30 에 그 카드를 내민다
> → 날짜가 같아 **그대로 통과한다.**

**막지 않았다.** 몇 시간이 지나야 오래된 것인지는 값이 아니라 판단이고, 이 서비스는 판단하지 않는다. 대신 **사실을 적었다** — 카드 머리에 `08:05에 답하신 내용입니다`. 직원은 그것을 보고 "그 뒤로 드신 것 없으시죠?" 를 **한 번만** 묻는다.

답한 시각이 URL 에도 실리므로 형식 판이 **1 → 2** 로 올라갔다. 판 1 주소는 읽지 않고 버린다 — 그대로 읽으면 **몇 시에 답한 카드인지 모르는 채로 🟢 가 그려진다.**

> **주소 길이 한도를 40 → 44 로 올렸다.** `HHMM` 4자가 늘었다. 40 은 외부에서 온 제한이 아니라 스스로 정한 어림수였고 전체 주소가 90자 남짓이라 줄바꿈이 달라지지 않는다. **한도를 늘린 것이지 없앤 것이 아니다** — `lib/encode.test.ts` 가 계속 지킨다.

### 10. 혈당 200 이 당뇨 환자 카드에 없다 **[코드]**

룰셋에 `conditional[].card_note` 를 두고, 그 문항에 "예" 라고 답한 환자의 카드에만 붙게 했다.

> 접수 시 혈당을 측정합니다. 혈당이 200을 넘으면 검사 일정을 다시 잡습니다

**판정이 아니다.** 배지를 올리지도 내리지도 않고, 주의 항목과 섞이지도 않는다. 당뇨약을 쓰지 않는다고 답한 환자에게는 붙지 않는다.

## 🔴 열린 것 — 확인이 필요하다

### 2. kill switch 가 설명서와 다르게 동작한다 **[코드]**

PRD §18 R5 가 **"재배포 없이 즉시 반영될 것"** 을 조건으로 걸었는데, Vercel 은 환경변수를 **그 배포에 묶는다.** 대시보드에서 값만 바꾸면 이미 돌아가는 배포는 예전 값을 그대로 들고 있다. `NEXT_PUBLIC_` 접두사를 떼도 마찬가지다.

**스위치가 고장난 것이 아니라 설명서가 틀렸다.** 값 변경 + 재배포까지 약 1분이면 정상 작동한다.

> **잃는 1분보다 모르는 채로 헤매는 5분이 비싸다.** 사고 난 순간은 이미 당황한 상태이고, 값을 바꿨는데 화면이 그대로면 "내가 잘못 눌렀나" 로 시간을 쓴다.

절차는 PRD §18 R5 "끄는 절차" 에 적었다. **남은 것은 실측이다.**

- [ ] 평상시에 한 번 껐다 켜 본다 (PRD §18 R5 절차대로)
- [ ] `NEXT_PUBLIC_SERVICE_STATUS` 는 **Sensitive** 라 값을 되읽을 수 없다. 되돌릴 때는 `live` 로 덮어쓴다
- [ ] **되돌릴 때도 Redeploy 를 빠뜨리지 않는다** — 값만 바꾸면 점검 화면이 남는다

> 한 번도 눌러 본 적 없는 비상 버튼은 있는지 없는지 모르는 것과 같다.

## 🟡 열린 것 — 실제 예약 시간표를 알아야 판단된다

### 3. 예약 시각이 8~17시로 하드코딩돼 있다 **[코드]**

`components/ReservationForm.tsx` 의 `HOURS = [8..17]`.

- **그 밖의 시각에 예약된 환자는 진입 자체가 불가능하다.** 버튼이 비활성인 채로 끝나고 이유도 알려주지 않는다
- `lib/schedule.ts` 는 00:30 · 05:00 · 06:00 예약까지 테스트로 검증해 두었는데 **폼이 그 값을 만들어낼 수 없어** UI 로는 도달 불가다
- 아키텍처 규칙 위반이기도 하다 — "검사별 차이는 룰셋 JSON으로만". 이 배열은 룰셋에 있어야 한다

**필요한 정보:** 7시대 · 18시대 슬롯이 실제로 있는가?

### 4. 답변은 10분 단위, 예약은 5분 단위 **[코드]**

룰셋 `questions.time.minute_step` 이 `10` (00/10/20/30/40/50) 인데 예약 분은 5분 단위다.

**예약 분이 5·15·25·35·45·55 면 판정선을 정확히 고를 수 없다.** 17:25 예약이면 당뇨 판정선이 `13:25` 인데 환자는 `13:20`(🟢) 아니면 `13:30`(🟡) 만 고를 수 있다. 정확히 지킨 환자가 자기 답을 표현할 방법이 없다.

절반의 예약에서 경계가 어긋난다. `minute_step` 을 5 로 맞추면 정렬되지만 선택지가 12개로 늘어난다.

**필요한 정보:** 예약 분이 정말 5분 단위인가?

### 9. 시각 입력이 3단 조작이다 **[재현]**

→ W3 관찰에서 실제 소요 시간을 재고 판단한다.

## ⚪ 기록만

### 11. 🟢 카드가 직원의 문진을 생략시킨다 **[관찰]**

**이 서비스의 본질적 위험이다.** KPI 가 "문답 시간 단축" 이므로 **설계 자체가 직원에게 생략을 유도한다.** 그런데 카드의 모든 값은 환자 자가응답이고 서비스는 그것을 검증하지 않는다(원칙상 못 한다).

🟢 문구 "접수처에 추가로 말씀하실 내용이 없습니다" 는 룰셋의 **행동 지시**이지 사실 확인이 아니다. 직원이 이것을 "확인 완료" 로 읽기 시작하면 환자 오답이 그대로 통과한다. Disclaimer 는 환자용 화면 하단에 있지 직원의 습관에는 닿지 않는다.

**W3 대기실 관찰에서 같이 기록할 것:**
- [ ] 직원이 카드를 보고 **무엇을 안 묻는가**
- [ ] 카드를 낸 환자와 안 낸 환자에게 묻는 항목이 어떻게 다른가

지금 코드로 할 일은 없다. **관찰 항목이다.**

### 12. 공유 링크에 건강 답변이 다 들어 있다 **[코드]**

`#` 뒤라 서버 로그에는 안 남지만(설계 의도대로) **카카오톡 대화방에는 그대로 남는다.** "가족에게 보내기" 의 정상 동작이라 결함은 아니지만, 잘못 보낸 링크는 회수가 안 된다.

### 13. `favicon.ico` 404 **[재현]**

프로덕션 콘솔의 유일한 에러다. `app/icon.png` 하나로 끝난다. 기능 영향 없음.
