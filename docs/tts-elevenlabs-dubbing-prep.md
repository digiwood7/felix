# PET Time 읽어주기 → 일레븐랩스 더빙 준비

## 1. 대본이 만들어지는 구조 (분석 결과)

대본은 **고정 텍스트 파일이 아니라 실행 시점에 조립된다.**

```
lib/rules/f18-fdg-pet.json  (문구 원천 — intro, speech_text, notes 전부 여기)
        │
lib/schedule.ts             (예약 시각으로 타임라인 계산)
        │
lib/speech.ts  speechBlocks() (문구 + 계산된 시각 → "도막" 배열)
        │
components/SpeakButton.tsx  (Web Speech API로 낭독, rate 0.7, 도막 사이 800ms 쉼)
```

- **도막(block)** = 쉬지 않고 이어 읽는 단위. `인트로 · 날짜별 하루 · Disclaimer` 가 각각 한 도막.
- 시각은 `koreanTime.ts` 가 "오전 2시" 처럼 말로 변환. `{time}` 슬롯이 문장 안에 들어가는 항목(도착)과, 시각을 독립 문장으로 앞세우는 항목(금식·검사)이 있다.
- 기호 정리는 `speech.ts` 가 이미 해 놓았다: `·` → `,` / `—` → `, ` / 문장 끝 마침표 보장.
- 대본 규칙은 `lib/speech.test.ts` 가 잠그고 있다 — **화면과 같은 내용을 같은 순서로** 읽는 것이 제1원칙.

```

[도막 2] 8월 19일 수요일. 하루 종일. 등산, 헬스, 골프 등 과격한 운동을 하지 마세요.

[도막 3] 8월 20일 목요일. 오전 2시. 이 시각 이후 아무것도 드시지 마세요.
물(생수)만 가능합니다. 보리차, 커피, 우유, 주스, 껌, 사탕도 안 됩니다.
단, 같은 날 다른 검사가 있으면 반드시 확인 후 생수를 드시기 바랍니다.

접수 시 혈당을 측정합니다. 혈당이 200을 넘으면 검사 일정을 다시 잡습니다.
오전 8시 25분. 검사 시작, 약 1시간 20분 소요됩니다.
검사실에서는 이렇게 진행됩니다. 약 5분 동안 주사를 맞습니다.
약 50분 동안 대기실에 누워 쉽니다. 대기실 주의사항을 알려드리겠습니다.
걷거나 움직이지 마시고 편히 누워 계세요. 휴대폰은 보셔도 됩니다.
보호자는 1명까지 대기실에 함께 계실 수 있습니다. 화장실은 중간에 가셔도 됩니다.
약 5분 촬영 직전 화장실에 다녀옵니다. 약 20분 동안 촬영합니다.

[도막 4] 이 서비스는 병원 공식 서비스가 아니며, 검사 가능 여부를 판단하지
않습니다. 최종 확인은 반드시 핵의학과 직원에게 받으세요.
```

## 3. 고정 vs 변동 — 무엇이 원테이크가 되는가

전체를 한 파일로 미리 더빙할 수는 없다. **환자마다 바뀌는 값이 5종** 있기 때문이다.

| 변동 슬롯 | 값의 범위 | 근거 |
|---|---|---|
| 날짜 + 요일 ×2 (전날 · 당일) | 연중 날짜 | 예약 날짜 |
| 금식 시각 | **정각만** (floor_hour) | `fasting.round` |
| 당뇨약 시각 | **정각만** (floor_hour) | `conditional.round` |
| 도착 시각 (+"까지") | **10분 단위** (floor_10min) | `arrival.round` |
| 검사 시작 시각 | **10분 단위** (S1 분 선택기 `minute_step: 10`) | `questions.time` |
| 건물 이름 | 2개 (본관 / 암병원) | `locations.options` |

나머지는 전부 고정 문장이고, 변동 슬롯이 **대부분 문장 경계(마침표)에 앉아 있다** — 원래 설계가 시각을 독립 문장("오전 2시.")으로 앞세우는 구조라, 이어붙이기(스플라이스)에 유리하다. 예외는 도착 문장 하나("오전 8시까지 ~로 오셔야 합니다" — 시각이 문장 안).

### 원테이크 구간 설계 (7개)

녹음(생성) 단위. ⏱는 rate 0.9 기준 대략 길이.

| # | 구간 | 성격 | 내용 |
|---|---|---|---|
| **A** | 인트로 | 완전 고정 ⏱4초 | "PET 검사를 위한 주의사항을 날짜와 시간별로 알려드리겠습니다." |
| **B** | 운동 제한 | 완전 고정 ⏱6초 | "하루 종일, 등산, 헬스, 골프 등 과격한 운동을 하지 마세요." |
| **C** | 금식 본문 | 완전 고정 ⏱17초 | "이 시각 이후 아무것도 드시지 마세요. 물, 생수만 가능합니다. 보리차, 커피, 우유, 주스, 껌, 사탕도 안 됩니다. 단, 같은 날 다른 검사가 있으면 반드시 확인 후 생수를 드시기 바랍니다." |

### 변동 조각 풀

| 풀 | 형태 | 개수 | 쓰는 곳 |
|---|---|---|---|
| 정각 시각 | "오전 2시." | 24 | 금식 C 앞, 당뇨 D 앞 |
| 분 시각 | "오전 8시 25분." → 실제로는 10분 단위 "오전 8시 20분." | 120 (12시간×2×5분값) | 검사 F 앞 |
| 도착 시각+까지 | "오전 8시까지" / "오전 8시 20분까지" | 144 (24 정각 + 120 분) | 도착 E 앞 (문장이 이어지므로 **끝을 올리지 않는 억양**으로) |
| 날짜+요일 | "8월 20일 목요일." | 연 단위 ~365 → **지연 생성 + 캐시** 권장 | 도막 2·3 첫머리 |

합계 약 300조각 + 날짜. 글자 수로 6천 자 안팎이라 일레븐랩스 비용은 무시할 수준이다.

## 4. 일레븐랩스 생성 시 지침

1. **모델**: `eleven_multilingual_v2` (안정) 또는 v3 (표현력 ↑, 알파). 고지·안내 톤이므로 v2 + 높은 stability 권장.
2. **속도**: 현행 Web Speech `rate 0.7` 의 의도(고령자가 받아 적는 속도)를 살린다 → `voice_settings.speed` 0.85~0.9. 너무 느리면 오히려 어색하니 실청취로 확정.
3. **목소리 방향**: 병원 안내 방송이 아니라 **간호사가 차분히 일러주는 톤**. 차분·또박또박·낮은 스타일 과장 (stability 0.7↑, style 0.2↓).
4. **이음새 자연화 — request stitching 사용**: 조각 생성 시 `previous_text` / `next_text` 파라미터에 실제 앞뒤 문장을 넣어 억양이 이어지게 한다. 특히:
   - 시각 조각 "오전 8시까지" 는 `next_text: "암병원 지하 1층 핵의학과로 오셔야 합니다."` 를 줘서 문장 중간 억양으로 생성.
   - 정각 조각 "오전 2시." 는 `next_text: "이 시각 이후 아무것도 드시지 마세요."`.
5. **발음 정규화 (생성용 텍스트만 손질, 화면 문구는 불변)**:
   - "물(생수)만" → "물, 생수만" (괄호는 낭독 사고 지점)
   - "1명까지" → 그대로 두되 "한 명"으로 읽히는지 확인
   - "혈당이 200을" → "이백" 으로 읽히는지 확인, 이상하면 "이백"으로 표기
   - 숫자+단위("6시간", "1시간 20분", "50분")는 한국어 모델이 대체로 잘 읽지만 **전 조각 실청취 검수 필수**
6. **출력 포맷**: mp3 44.1kHz 96kbps mono면 충분. 도막3 전체가 조립돼도 1MB 미만.

## 5. 재생 쪽 통합 방향 (다음 단계)

- 조각을 정적 파일(`public/audio/…` 또는 CDN)로 두고, 재생 시 순서대로 이어붙인다 (HTMLAudio 순차 재생 또는 Web Audio 게이플리스 연결). 도막 사이 800ms 쉼은 현행 유지.
- **조립 순서는 `speechBlocks()` 출력과 1:1** — 화면=소리 일치 원칙(§ speech.test.ts)을 깨지 않으려면 speech.ts 의 도막 구조를 오디오 매니페스트 생성에 재사용한다.
- 파일명 규약 예: `time-am-08-20.mp3`, `time-until-am-08-20.mp3`, `date-08-20-thu.mp3`, `seg-fasting.mp3`, `seg-exam.mp3`, `seg-arrival-cancer.mp3`.
- **폴백**: 오디오 로드 실패(3G·오프라인) 시 현행 Web Speech API 경로를 그대로 유지. `SpeakButton` 의 "한국어 음성 없으면 버튼 숨김" 규칙은 "일레븐랩스 오디오가 있으면 항상 표시"로 완화 가능.
- 성능 예산: 첫 화면 1.5초 예산(§13)에 오디오가 끼면 안 된다 — **버튼 누른 뒤에만 로드**, 첫 조각 재생 중 나머지 프리페치.
- 런타임에 일레븐랩스 API를 직접 부르지 않는다(사전 생성 방식) — 예약 시각이 외부 API로 나가지 않아 §14 개인정보 논리가 그대로 유지되고, 지연·비용·키 노출 문제도 없다. 날짜 조각만 서버리스에서 지연 생성+캐시(같은 날짜는 1회 생성).

## 6. 열어 둔 결정 (대표 확인 필요)

1. **목소리 선택** — 일레븐랩스 보이스 라이브러리에서 한국어 여성/남성 후보 2~3개 시청 후 결정.
2. 날짜 조각을 "연간 일괄 생성"으로 갈지 "지연 생성+캐시"로 갈지.
3. `speak` 버튼 노출 조건 변경 여부 (오디오 파일 기반이면 모든 기기에서 표시 가능).
